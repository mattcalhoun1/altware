Transports

LoRa, ISM bands, and MQTT

The protocol is built for any path that can move bytes, including unreliable ones. Delivery, retries, signatures, encryption, and route choice sit on each device.

Protocol agnostic, fault tolerant

Blackout Comms does not assume a reliable link or any security from the radio itself. Each device validates signatures and payloads, encrypts and decrypts, retries, and decides which method and path to use. That holds whether a cluster has 2 devices or 90.

LoRa and the ISM bands

LoRa is a long-range, spread-spectrum modulation from Semtech. It is a practical fit here: low power, low cost, and a wide selection of modules, antennas, and amplifiers. It is an open standard, and many vendors ship hardware for it.

ISM means industrial, scientific, and medical. In the US the relevant unlicensed range is 902–928 MHz, along with the more familiar 2.4 and 5.8 GHz bands, provided the equipment stays inside FCC limits. Other countries use different ranges. ChatterBox primarily uses 902–928 MHz and can also use 863–870 MHz.

Frequency hopping

Whatever range is in use, the cluster hops. Devices move together to a short-lived base frequency chosen by a key-dependent algorithm. That cuts collisions between clusters and limits how long jamming on one frequency can matter.

On a direct exchange, the first packet uses the rotating base frequency. The rest are striped across frequencies known only to those two devices, typically within milliseconds.

MQTT and Wi-Fi

MQTT is the secondary path: low overhead, no delivery guarantee, and a good fit for constrained devices. It runs over 2.4 GHz Wi-Fi, which is a very different medium from LoRa, so it widens the platform without giving up the decentralized security model. TLS is possible, but it costs memory, so it is a choice rather than a requirement.

MQTT is optional. When it is available — a phone hotspot, Starlink, or any other 2.4 GHz internet source — it is just another hop, and it can bridge distances LoRa cannot.

Other methods

UDP multicast over Wi-Fi has been tested and works. It is currently disabled in the firmware because extra transports make the system harder to understand. UDP needs more networking setup than MQTT and has no server in the middle.
